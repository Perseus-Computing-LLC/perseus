# Sanitized real Perseus Vault semantic-density replay

This benchmark uses a bounded, sanitized export of the local shared Vault and
replays it through the **real Perseus Vault MCP binary** against an owned,
fresh temporary database. It is offline: no network, LLM, embeddings, Greg,
AWS, or persistent Vault database access.

All live replay writes use `EphemeralAdmissionFixture`. The fixture registers a
synthetic agent, installs an enforce-mode authority manifest, creates the
hash-bound admission source event, and writes records through the public
`perseus_vault_remember` API. Its database and per-run HMAC key are process-local
and removed after the run; no personal database or long-lived credential is
used. The ordinary unauthenticated write path remains a separate negative
contract and must stay proposed/non-serveable.

## Source and privacy boundary

The source was a read-only Vault scan of the active `capture` category. The
scan returned 30 active entries. The committed replay corpus contains the
first 24 non-empty entries after deterministic shaping.

`sanitize.py` removes operational metadata and redacts these classes from
content and summaries:

- GitHub and AWS credential patterns;
- private-key blocks;
- secret/token/password assignments;
- signed URL query credentials;
- email addresses and phone numbers;
- absolute local paths.

The corpus does **not** contain `body_json`, entity IDs, workspace hashes,
agent IDs, timestamps, retrieval counters, or Vault links. IDs in the replay
report are newly generated by the temporary Vault database and are not source
IDs.

The source scan artifact was temporary-only and is not part of the repository.
The committed corpus is 30,909 bytes; the replay result is 2,059 bytes.

## Rebuild the corpus

Given a local JSON capture from `perseus_vault_scan` (or a fixture with an
`items` array):

```bash
uv run --no-project python benchmark/real_vault_density/sanitize.py \
  /path/to/scan.json \
  benchmark/real_vault_density/sanitized_corpus.json \
  --max-items 24
```

The sanitizer is deterministic and bounded. Review the generated corpus before
sharing it outside the local checkout. Regex redaction is a safety layer, not
a proof of semantic de-identification.

## Run the replay

Build or obtain a current `perseus-vault` binary, then run the governed
synthetic density gate:

```bash
uv run --no-project --with pyyaml python benchmark/real_vault_density/run.py \
  --bin /path/to/perseus-vault \
  --out benchmark/real_vault_density/results.json
```

The harness owns a temporary Vault database and writes the deterministic dataset
through the authenticated fixture. It then recalls every expected category/key
address and applies both:

- the production decoder-backed serving budget;
- the legacy relevance-only budget.

For the sanitized corpus and fixed retrieval probes, pass `--corpus` and,
optionally, `--probes`:

```bash
uv run --no-project --with pyyaml python benchmark/real_vault_density/run.py \
  --bin /path/to/perseus-vault \
  --corpus benchmark/real_vault_density/sanitized_corpus.json \
  --probes benchmark/real_vault_density/probes.json \
  --out benchmark/real_vault_density/probe_results.json
```

The corpus contains historical natural-language text that intentionally trips a
soft admission-lint pattern. The corpus/probe lane therefore uses Vault's
documented operator-only `PERSEUS_VAULT_DISABLE_ADMISSION_LINT=1` escape hatch
inside the owned fixture process only, so it can measure serving without
weakening normal Vault clients. The synthetic gate and the unauthenticated
negative-contract test run with the lint boundary enabled.

The corpus replay uses a 160-character serving budget. It measures selection
fraction, omitted-item count, prompt-token estimate, and decoder coverage. The
six-probe measurement-only retrieval/task replay uses a separate 640-character
budget so the probes test retrieval plus realistic answer-bearing context,
without turning the diagnostic into an artificial truncation test. The probes
are deliberately not a pass/fail gate.

The synthetic adversarial fixture remains the correctness gate for task
resumption and load-bearing retention. The sanitized probes measure the
combined behavior of Vault lexical retrieval plus serving compression and
should be read as diagnostic evidence, not a benchmark leaderboard claim.

## Result

The checked-in result below is a historical 2.22 reference measurement. It is
not used as the live pass/fail assertion; the authenticated replay above
regenerates its report against the selected Vault binary and verifies the
category/key retrieval set and density gate on every run.

Against `perseus-vault 2.22.0 (a9524e9)`:

```text
24 sanitized source items
23 omitted under the 160-character budget
production decoder coverage: 1.0000
legacy decoder coverage:      0.0000
production prompt estimate:   39 tokens
uncompressed estimate:        5,499 tokens
network calls:                0
gate: PASS
```

The 39-token value is the served text for the highest-ranked item in this
particular corpus, not a claim that every source fact fits into 39 tokens. The
important result is that omitted items retain content-free decoder references.

The measurement signature in `probe_results.json` (`probe_replay_signature`) is
reproducible from the case results and excludes Vault-generated entity IDs,
which can change across fresh-database runs. Use that signature for audit and
the `signature_sha256` for file integrity.

The report signature covers the corpus metadata and all case results. It can be
checked with the benchmark module's `verify_report_signature()` helper.

## Probe result

The six fixed probes use a 640-character budget and unique target phrases so
that the diagnostic does not depend on broad-query FTS tie ordering. Two fresh-
database runs produced identical rows and the same `probe_replay_signature`:

```text
hit@5:                       1.0000
MRR:                         1.0000
production task resumption:  0.8333
production decoder coverage: 0.0000
legacy task resumption:      0.8333
legacy decoder coverage:     0.0000
probe_replay_signature:      54ce766e9910e60c78e788b5947f6219f577a26d8536ea610a8b268a280b51a6
```

The zero probe decoder-coverage value is expected: the unique probes keep their
answer-bearing target visible. Decoder recovery under severe omission pressure
is measured separately by the 160-character, 24-item corpus gate above.

## Infrastructure decision

AWS is not justified: this is a 24-item, 30 KB offline corpus. Greg was not
needed and the SSH endpoint was unreachable during the attempt. A future Greg
run should use an explicitly exported, reviewed corpus—not direct production
DB access—and should be separately authorized if the source contains real
operational material.

Regression tests:

```bash
uv run --no-project --with pytest --with pyyaml python -m pytest \
  tests/test_real_vault_sanitizer.py \
  tests/test_real_vault_density_benchmark.py -q -m 'not slow'
```

The live replay is opt-in and uses the benchmark-specific binary variable so
ordinary test runs cannot accidentally touch a personal Vault installation:

```bash
PERSEUS_VAULT_BENCHMARK_BIN=/path/to/perseus-vault \
  uv run --no-project --with pytest --with pyyaml python -m pytest \
  tests/test_real_vault_density_benchmark.py -q
```

This runs the authenticated replay, the fixture cleanup check, and the distinct
unauthenticated proposal/recall negative contract.

The sanitized corpus and result are review artifacts, not a production backup.
Do not restore them into the live Vault.
